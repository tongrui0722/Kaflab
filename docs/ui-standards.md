# KAFLAB 界面规范

这份规范对应当前界面。组件样式集中在 `frontend/src/ui-system.css`；新增页面先使用其中的字级与控件规则，再补充页面特有布局。

## 信息顺序

页面按「当前位置与状态 → 主要数据或主要操作 → 诊断详情」排列。页头只保留页面名称、必要状态和一个主要动作。集群概览先显示健康、Lag 和在线 Broker；操作页先显示目标与执行按钮，追踪、原始报文和历史记录置于相邻面板或折叠区。

桌面布局优先让操作区、结果区在首屏并排，长表格和日志在各自面板内滚动。窄屏纵向排列，保持导航、筛选和主要按钮可访问，不允许页面横向溢出。

## 字体与内容

| 层级 | 字号 | 用途 |
| --- | ---: | --- |
| 页面标题 | 18px | 当前页面或集群名称 |
| 面板标题 | 14px | 卡片、表格与配置段落 |
| 正文 | 13px | 结果、列表与常规信息 |
| 表单标签、按钮、表格 | 12px | 字段和可操作内容 |
| 辅助说明 | 11.5px | 单行提示、时间、口径与空状态 |

字体使用系统无衬线字体栈，避免依赖客户端额外安装字体。IP、Topic、Offset、HEX 与日志使用等宽数字或等宽字体。浅色背景上的正文和数据使用深蓝灰文字，辅助文字也须保持可读；颜色只表示状态或交互层级。控件文字保持适度行高，在按钮、输入框与选择框上下留出空间；主要指标数字保持原有强调字号，不随普通文字整体缩小。

辅助说明只在默认值含义、数据口径、限制条件或下一步动作不明显时出现。重复标题、重复字段名称、宣传式说明和对当前值的复述应删除。错误原因与恢复动作使用提示条或就近状态，不混在灰色辅助说明里。空状态用一句话说明下一步，例如“选择 Topic 后读取消息”。

## 控件与状态

主按钮用于每个区域最关键的动作；次要动作使用统一浅色按钮，危险操作使用红色语义。筛选框和下拉框保持一致高度、边框、箭头与键盘焦点样式。Topic 搜索选择框支持键盘筛选和选择，仍允许直接输入名称；结果列表在面板滚动区内完整可见，键盘移动时跟随当前选项，点击外部关闭。

状态同时使用文字与颜色：绿色为正常或成功，蓝色为进行中或当前选择，橙色为警告，红色为失败，灰色为未知或空。状态徽章使用一致的圆角、字号与轻量阴影；不能只靠颜色表达状态。

运行日志按真实日志级别强调错误；`stderr` 只是进程输出通道，不能单独作为报错依据。结构化投递、消费事件与客户端原始输出分别展示。

## 验证基线

每次修改至少运行前端构建，并在 1440px 桌面和 390px 窄屏检查所有主路由。重点确认没有横向溢出、按钮和字段可访问、Topic 筛选可用、独立滚动区域可用、页头及弹层不会遮挡内容。涉及数据请求或计数的修改还需验证相应接口与异常状态。
