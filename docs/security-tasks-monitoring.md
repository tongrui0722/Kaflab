# 安全、后台任务与监控

## 登录和授权

除登录、健康探针及预检请求外，服务端要求所有 `/api/` 请求携带有效登录令牌；WebSocket 使用登录令牌建立连接。令牌保存在服务内存，重启或退出登录后失效。只读模式保留集群新增能力，其余修改操作需要“全部功能”模式。

本地 `users.json` 可以为账号设置 `role`（`admin` 或 `viewer`）、`clusters`（允许访问的集群 ID 列表）及 `operations`（允许的操作权限列表）。省略这两个列表表示不限制；`viewer` 不能切换到全部功能。常用操作权限包括 `cluster:write`、`cluster:delete`、`topic:create`、`topic:delete`、`topic:expand`、`topic:reassign`、`group:offset_reset`、`alert:manage`，其余写操作使用 `api:write`。只读查询仍须登录，受 `clusters` 限制。 设置了集群范围的账号仅能使用带集群 ID 的接口、任务查询和客户端版本目录；全局 Trace、压测、模拟运行记录等无法归属集群的接口会拒绝访问。服务端将修改请求的用户、路径、时间和结果写入 `audit.jsonl`。

集群 API 只返回 `hasSaslPassword`，不返回密码。受管集群的客户端模拟、压测和工作台由服务端读取凭据。新保存的 Kafka 密码在 `clusters.json` 中使用 Fernet 加密；旧明文配置在加载时迁移。密钥优先取 `KCL_SECRET_KEY`，未设置时自动生成数据目录下的 `.kaflab.key`。**备份或迁移时必须一起保存密钥与 `clusters.json`；密钥丢失后无法恢复原有密码。** 历史备份中的明文密码不会被自动清除，需要按备份管理策略处理。直接填写的独立 Kafka 地址及密码仍由用户提交给服务端，请使用可信的 HTTPS 接入方式。

## Topic 删除后台任务

在 Topic 详情页提交删除后，平台保存任务到 `operations.db`，进入“操作任务”查看状态、每次重试原因、下一次尝试时间和最终核对结果。刷新页面或重启服务后，未完成的任务会继续。服务端先确认 Topic 是否存在，再发送删除请求；收到 `NOT_CONTROLLER` 等暂时性错误会重新获取元数据并重试。最多执行 9 次，默认退避间隔依次为 1、2、4、8、15、20、30、30 秒。成功条件是再次查询 Kafka 元数据确认 Topic 已消失。超时后任务标记失败，可根据事件记录排查。

后台任务只负责已明确提交的 Topic 删除；不会自动重试其他管理操作，也不能绕过 Kafka 权限或错误的 `advertised.listeners`。任务完成并不代表下游消费组位移、外部缓存或其他系统已清理。

## 监控与告警

“监控与告警”页面显示 Broker/Topic 状态、趋势、采样时间、Lag 状态、当前告警及事件。后台健康采集默认每分钟一次，单集群限时 30 秒；Lag 采集继续按现有 `KCL_LAG_INTERVAL_SECONDS` 和 `KCL_LAG_TIMEOUT_SECONDS` 配置。采集不依赖浏览器是否登录。

健康样本及事件保存在 `monitoring_samples.db`，默认保留 3 天。可配置离线 Broker、离线 Topic、副本不足 Topic 和 Lag 的阈值。页面区分“确有异常”“采集失败”“部分采集失败”“数据过期”；超过 150 秒的健康样本不会作为当前告警。规则触发、恢复及采集失败会记录到平台内事件。当前版本仅提供平台内告警和事件查询，尚无外部通知通道。

## 消费组位移治理与 Topic 列表

消费组支持对指定 Topic 预览“最早/最新”位移。服务端要求消费组无活跃成员；预览令牌有效期 120 秒。执行前再次核对消费组状态、分区数和当前位移，并要求输入完整 Group ID 确认。执行逐分区写入位移并回查，结果可能为部分成功，详细结果记录于 `group_offset_audit.jsonl`。执行前请停止消费程序，并核对预览中每个分区的目标位移。

Topic 列表由服务端按名称、健康状态排序和分页。Kafka 元数据本身仍需完整拉取，服务端缓存 30 秒以减少重复请求；页面显示采样时间并提供强制刷新。列表性能收益主要体现在浏览器响应体和短时间重复查询，大集群首次拉取仍受 Kafka 元数据请求耗时影响。

## 数据备份

Docker 部署时，以上数据库、日志、`clusters.json` 和 `.kaflab.key` 都应保存在持久挂载的 `/data`。备份时保持文件与密钥来自同一个实例。恢复后检查数据目录权限，再启动服务。
